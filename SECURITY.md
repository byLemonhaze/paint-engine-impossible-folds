# Security and private release handling

Do not include wallet seed phrases, private keys, access tokens, or personal credentials in issues, logs, recipes, or commits. Inscription IDs and content hashes are public identifiers once inscribed.

Report suspected vulnerabilities privately to the repository owner through an existing private contact channel. Use GitHub private vulnerability reporting only if available and enabled for this repository. Include reproduction steps, affected version, and impact; avoid public disclosure before a fix is agreed.

No repository script submits transactions or manages a wallet. Review externally supplied recipes/HTML before using them. Keep the repository private during inscription preparation; making it private cannot revoke copies downloaded while it was public.
